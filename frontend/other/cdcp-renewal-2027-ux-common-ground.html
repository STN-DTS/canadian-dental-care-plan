Before you start: UX mockup vs common ground

Both panels show the same page. The common ground version adopts the Figma patterns and keeps only the changes listed under “What’s still different”.

Pick a state to show it in both panels, or click through each panel yourself. Open a view on its own: UX mockup (as proposed) or Common ground.

Where we already agree

  • “Complete” badge on finished sections
  • Answer summary replaces the description
  • “Edit answer” link with a pencil icon
  • “There is a problem” error summary
  • Card-level error with a red border
  • Next is never disabled
  • The “N of 2 sections completed” counter
  • Card layout
  • Descriptions that explain why each section is needed
  • Circle-check icon removed
  • Previous and Next cards on later hubs

What’s still different

  1. Not-started section entry: solid navy button-styled link vs a prominent text link with an arrow. The main accessibility concern (Space key, screen-reader and voice-control lists, solid navy means Save on the spokes). Figma already uses a link once a section is complete, so a link here makes both states consistent.
  2. Tax filing entry wording: “Confirm tax filing” vs “Answer the tax filing question”. This changes the error text too.
  3. “Not started” tag: none vs a tag.
  4. Next styling: open question, use the toggle.

What changed and why

Rows marked “Same” come first, then the differences, the open question and a note.
ElementUX mockupCommon groundWhy
Descriptions Same Each not-started card explains why the section is needed. Same. People know why we ask before they start.
Circle-check icon Same Removed. Same. It made unfinished sections look finished.
“Complete” badge Same Green “Complete” pill with a check, top-right. Same. The status is text, so it doesn’t rely on colour or an icon.
Completed card Same The answer summary replaces the description. Same. People can check their answer without opening the section.
“Edit answer” link Same Divider, then a pencil icon and an underlined “Edit answer” link. The button is gone. Same, plus hidden context for screen readers (“Edit answer for tax filing”). Several links named only “Edit answer” sound identical in a screen-reader links list.
Error summary Same “There is a problem” with numbered links, under the counter. Same. Each link moves focus to the card’s link. The error is announced and each message leads to the fix.
Card-level error Same Red border, and a warning line above the missing card naming the action to select. Same. People scrolling the cards see what’s missing in place. WCAG 3.3.1 is met by the summary; this is a usability extra.
Next never disabled Same Next stays enabled. Same. No unexplained disabled state. The error summary explains what’s missing.
Counter Same “N of 2 sections completed.” Same. Shows overall progress at a glance.
Card layout Same Title, description or answer, divider, then the action. Same. A familiar structure that is easy to scan.
Previous / Next Same Later hubs add an outlined “Previous” card with a left chevron, to the left of Next. Not on this hub. Same. Consistent navigation between hubs.
Icons Same Muted blue chevron circle in Next, check in the badge, pencil on “Edit answer”, warning triangle on card errors. Same, plus an arrow on the not-started entry link. All decorative and hidden from screen readers. Icons support the text. They never carry meaning on their own.
Not-started section entry Different Solid navy button-styled link. A prominent bold, underlined link with an arrow, in the same place. The main accessibility concern. Links go to a page; buttons act. A link dressed as a button breaks that: Space does nothing, and screen-reader and voice-control users look in the wrong list. Solid navy also means Save on the spokes. Figma already uses a link once complete, so this makes both states consistent.
Tax filing entry wording Different “Confirm tax filing” “Answer the tax filing question” Name the task, not a one-click result. This changes the error text too.
“Not started” tag Different None. “Not started” tag before a section is done. Every section shows its status as text, not only finished ones. A small difference.
Next button Open question Outlined until required sections are complete, then solid navy. Optional sections don’t count. Solid navy always (recommended). The toggle shows the Figma rule. One solid primary action per page, and a stable button is easier to find. To decide in the meeting.
Figma detail to check Note In the Figma error state the counter reads “0 of 2” while Terms shows Complete; probably a static-mockup slip.
